## 🎯 核心功能

### 1️⃣ 完整的通知多语言支持

所有通知内容都会根据用户语言偏好自动翻译，包括：

#### 申请提交通知
- **标题**：`application.submit.success`
- **内容**：`notification.application.submitted`
  - 模板：`您的【{itemName}】申请已提交，请等待审核。`
  - 事项名称 `{itemName}` 会自动翻译为对应语言

#### 状态变更通知
- **标题**：`notification.status.changed`
- **内容**：`notification.status.changed.content`
  - 模板：`您的申请状态已变更为【{status}】`
  - 状态 `{status}` 会自动翻译（待审核、处理中、已完成、驳回）
- **处理结果**：`notification.handle.result`
  - 前缀：`，处理结果：`

### 2️⃣ 事项名称多语言

- 从 `MultilingualInfo` 表获取翻译
- 支持事项名称、办理要求的完整翻译

### 3️⃣ 状态翻译

| 中文状态 | 键名 | 翻译示例（藏语） |
|---------|------|----------------|
| 待审核/待处理 | `application.pending` | སྒུག་ཡོད། |
| 处理中 | `application.processing` | ལག་ལེན་བྱེད་ཡོད། |
| 已完成/已通过 | `application.completed` | ཚར་ཡོད། |
| 驳回 | `application.rejected` | ཕྱིར་ལོག་ཐུབ་པ་ཡིན། |

### 核心工具类

#### `I18nUtils.java`

```java
// 获取翻译消息
public static String getMessage(String languageType, String key, String defaultValue)

// 翻译状态
public static String translateStatus(String languageType, String statusCn)
```

**特性**：
- ✅ UTF-8 编码加载 properties 文件
- ✅ 自动 fallback 到中文
- ✅ 支持简码和完整码（`bo` 和 `bo-CN` 都可用）

### 通知生成逻辑

#### 申请提交（`ServiceItemServiceImpl.submitApplication`）

```java
// 1. 获取用户语言偏好
String userLang = preferenceService.getUserLanguage(userId);

// 2. 获取事项名称（多语言）
String itemName = serviceItem.getItemName();
if (!"zh-CN".equals(userLang)) {
    MultilingualInfo mlInfo = multilingualMapper.selectByItemIdAndLanguage(itemId, userLang);
    if (mlInfo != null) {
        itemName = mlInfo.getItemNameTrans();
    }
}

// 3. 生成通知内容
String title = I18nUtils.getMessage(userLang, "application.submit.success", "申请提交成功");
String contentTemplate = I18nUtils.getMessage(userLang, "notification.application.submitted", 
    "您的【{itemName}】申请已提交，请等待审核。");
String content = contentTemplate.replace("{itemName}", itemName);

// 4. 发送通知
notificationService.sendNotification(userId, title, content, "APPLICATION_STATUS", recordId);
```

#### 状态变更（`ServiceItemServiceImpl.handleApplication`）

```java
// 1. 获取用户语言偏好
String userLang = preferenceService.getUserLanguage(userId);

// 2. 翻译状态
String translatedStatus = I18nUtils.translateStatus(userLang, status);

// 3. 生成通知内容
String title = I18nUtils.getMessage(userLang, "notification.status.changed", "申请状态变更");
String contentTemplate = I18nUtils.getMessage(userLang, "notification.status.changed.content", 
    "您的申请状态已变更为【{status}】");
String content = contentTemplate.replace("{status}", translatedStatus);

// 4. 添加处理结果（如果有）
if (handleResult != null) {
    String resultPrefix = I18nUtils.getMessage(userLang, "notification.handle.result", "，处理结果：");
    content += resultPrefix + handleResult;
}

// 5. 发送通知
notificationService.sendNotification(userId, title, content, "APPLICATION_STATUS", recordId);
```

## 🐛 已修复的问题

### 问题1：通知内容混合中文和少数民族语言
**原因**：语言代码不匹配
- 数据库使用 `bo`（藏语简码）
- 文件名为 `bo-CN.properties`
- `I18nUtils` 找不到文件，返回中文 fallback

**解决方案**：
- 创建简码版本的语言文件（`bo.properties`, `ug.properties`, `zh.properties`）
- 同时保留完整码版本（`bo-CN.properties`, `ug-CN.properties`, `zh-CN.properties`）
- 更新 `UserController` 使用 `startsWith()` 匹配语言代码

### 问题2：事项名称翻译了，但通知模板是中文
**原因**：`getMessage` 的 fallback 是硬编码的中文字符串

**解决方案**：
- 保留有意义的中文 fallback（兜底方案）
- 确保所有语言文件都有完整的翻译 keys
- 使用模板占位符 `{itemName}` 和 `{status}` 动态替换

### 问题3：少数民族语言显示乱码
**原因**：Properties 文件默认使用 ISO-8859-1 编码

**解决方案**：
- 使用 `new InputStreamReader(in, "UTF-8")` 显式指定 UTF-8 编码
- 确保所有 `.properties` 文件保存为 UTF-8 编码

## 📚 开发建议

### 添加新语言

1. 创建语言文件 `src/main/resources/languages/<语言代码>.properties`
2. 复制现有语言文件的结构
3. 翻译所有 keys
4. 在数据库 `MultilingualInfo` 表添加对应事项的翻译

### 添加新的翻译 keys

1. 在所有语言文件中添加对应的 key-value
2. 使用 `I18nUtils.getMessage(lang, key, fallback)` 获取翻译
3. 如果有占位符，使用 `.replace("{placeholder}", value)` 替换

### 性能优化建议

- 考虑缓存 Properties 对象（避免每次请求都加载文件）
- 使用数据库存储用户语言偏好（目前是内存存储）
- 对高频访问的翻译内容使用 Redis 缓存
