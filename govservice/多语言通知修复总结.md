# 多语言通知修复总结

## 🎯 核心问题

**现象**：通知内容混合显示中文和少数民族语言
```json
{
  "title": "申请提交成功",
  "content": "您的【ས་གནས་དུ་རྩ་ཁྲིམས་འགྲོ་བ】申请已提交，请等待审核。"
}
```

**预期**：完全显示少数民族语言
```json
{
  "title": "ཞུ་འདེམས་ཐུབ་པ་ཡིན།",
  "content": "ཁྱེད་ཀྱི་【ངོས་འདེབས་ཤོག་ལེབ་གཏན་འཇགས།】ཞུ་འདེམས་ཐུབ་པ་ཡིན། བསམ་བཀོད་སྒུག་པ་ཡིན།"
}
```

---

## 🔍 问题分析

### 问题1：语言代码与文件名不匹配

**数据库中的语言代码**：
```sql
INSERT INTO MultilingualInfo (ItemID, LanguageType, ItemNameTrans, ...)
VALUES (1, 'bo', 'ངོས་འདེབས་ཤོག་ལེབ་གཏན་འཇགས།', ...);
```

**用户设置的语言**：
```http
PUT /api/user/me/language?languageType=bo
```

**现有文件名**：
```
src/main/resources/languages/bo-CN.properties
```

**I18nUtils 加载路径**：
```java
String path = "languages/" + languageType + ".properties";
// 尝试加载: languages/bo.properties  ❌ 文件不存在
```

**结果**：`I18nUtils.getMessage("bo", "notification.application.submitted", "您的【{itemName}】...")` 返回中文 fallback。

---

### 问题2：事项名称翻译成功，但通知模板失败

**事项名称翻译**（✅ 成功）：
```java
MultilingualInfo mlInfo = multilingualMapper.selectByItemIdAndLanguage(1, "bo");
itemName = mlInfo.getItemNameTrans(); // "ངོས་འདེབས་ཤོག་ལེབ་གཏན་འཇགས།"
```

**通知模板翻译**（❌ 失败）：
```java
String contentTemplate = I18nUtils.getMessage("bo", "notification.application.submitted", 
    "您的【{itemName}】申请已提交，请等待审核。");
// 返回中文 fallback（因为找不到 bo.properties）
```

**最终结果**：
```java
String content = contentTemplate.replace("{itemName}", itemName);
// "您的【ངོས་འདེབས་ཤོག་ལེབ་གཏན་འཇགས།】申请已提交，请等待审核。"
```

## ✅ 解决方案

### 方案1：创建简码语言文件

为所有使用简码的语言创建对应的文件：

```

├── bo.properties          # 新增：藏语简码
├── bo-CN.properties       # 保留：藏语完整码
├── ug.properties          # 新增：维吾尔语简码
├── ug-CN.properties       # 保留：维吾尔语完整码
├── zh.properties          # 新增：中文简码
└── zh-CN.properties       # 保留：中文完整码
```

**实现**：

```java
// 复制 bo-CN.properties 内容到 bo.properties
// 复制 ug-CN.properties 内容到 ug.properties
// 复制 zh-CN.properties 内容到 zh.properties
```

---

### 方案2：更新语言代码匹配逻辑

**原代码**（`UserController.java`）：
```java
i18nConfig.put("direction", ("ug".equals(lang) || "kk".equals(lang)) ? "rtl" : "ltr");
i18nConfig.put("verticalWriting", "bo".equals(lang));
```

**问题**：无法同时支持 `bo` 和 `bo-CN`

**修复后**：
```java
i18nConfig.put("direction", (lang.startsWith("ug") || lang.startsWith("kk")) ? "rtl" : "ltr");
i18nConfig.put("verticalWriting", lang.startsWith("bo"));
```

**效果**：同时支持 `ug`, `ug-CN`; `bo`, `bo-CN`

---

### 方案3：更新 translateStatus 方法

**原代码**（`I18nUtils.java`）：
```java
if (languageType == null || "zh-CN".equals(languageType)) {
    return statusCn;
}
```

**问题**：使用 `zh` 简码时，状态不会被翻译

**修复后**：
```java
if (languageType == null || "zh-CN".equals(languageType) || "zh".equals(languageType)) {
    return statusCn;
}
```

**效果**：支持 `zh` 和 `zh-CN` 两种代码

## 🎯 最佳实践总结

### 1. 语言文件命名规范
- 同时提供简码和完整码版本
- 简码：`bo.properties`, `ug.properties`, `zh.properties`
- 完整码：`bo-CN.properties`, `ug-CN.properties`, `zh-CN.properties`

### 2. 语言代码匹配
- 使用 `startsWith()` 而不是 `equals()`
- 可以同时匹配 `bo` 和 `bo-CN`

### 3. 占位符使用
- 模板使用 `{placeholder}` 标记动态内容
- 先获取模板，再使用 `.replace()` 替换占位符
- 确保占位符内容也被翻译（如事项名称）

### 4. Fallback 策略
- 保留有意义的中文 fallback（作为兜底方案）
- 不要使用空字符串作为 fallback
- 确保所有语言文件都有完整的翻译

### 5. UTF-8 编码
- 使用 `new InputStreamReader(in, "UTF-8")` 显式指定编码
- 所有 `.properties` 文件保存为 UTF-8 编码
- 避免使用 native2ascii 转换工具
